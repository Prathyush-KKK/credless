## 2. Playwright features that replace (or shrink) our hand-written code

Verified against the release-notes source in `microsoft/playwright` unless noted.

1. **Test locks** (1.63 `lock` on `test`, 1.64 `test.describe.configure({ lock })`): "tests that share a lock name never run concurrently, across files, workers and projects". Replaces most of the per-worker namespace juggling for personas: lock on `persona:owner` instead of pre-allocating `a0..a3` account sets. Keep namespaces only for true parallelism.
2. **`TestProject.default: false`** (1.64): keep `selftest` and real projects in one config; `npx playwright test` runs only defaults, `--project="*"` runs all. Removes the the target variable branching in `playwright.config.ts`.
3. **`retryStrategy: 'isolated'`** (1.62), **`--shuffle <seed>`** (1.64), **`failOnFlakyTests`** (config 1.52, CLI 1.45), `--repeat-each`: the flake story. Keep the two-run `--twice` compare but build it on the **blob reporter + `merge-reports`** rather than diffing two `results.json`.
4. **`Reporter.preprocess()`** (1.62): a reporter can skip/exclude/mark tests before `onBegin`. Use it for "test API health failed → skip everything that needs it" instead of throwing from worker fixtures.
5. **`--add-reporter`** (1.63): users bolt on CTRF/OTel/Allure without editing the kit's config. **HTML `mergeFiles`** (1.62), `title` (1.53), **`noSnippets`** (1.54, fewer source lines in the report, smaller leak surface), `captureGitInfo` (1.51).
6. **Structured evidence via steps**: `test.step` `box`/`timeout`/`location` (1.48–1.50), `subtitle`/`params` (1.63), **`TestStepInfo.attach()`** (1.51), `TestStep.attachments` exposed to reporters (1.50). Attach shots to steps instead of a parallel `shots/` tree; the HTML report shows a step waterfall (1.63).
7. **Trace `snapshots: { dom, aria, screen }`** (1.63) and "Display Aria" mode: aria-only traces are text, so the scrubber can redact them fully; `page.ariaSnapshot()` (1.59) / `ariaSnapshotJSON` (1.63) give agent-readable, scrubbable evidence; `toMatchAriaSnapshot` with YAML files (1.49/1.50); `Page.ariaSnapshot({ mode: 'ai' })` + `getByRef('e2')` (1.64).
8. **Guard bookkeeping**: `page.consoleMessages()`, `pageErrors()`, `requests()` (1.56), `ConsoleMessage.timestamp()` and `clearConsoleMessages()` (1.59), `WebError.location` (1.60), `TestInfoError.errorContext` (1.60), context-level lifecycle events mirrored from pages (1.60). Most of `guard.ts`'s per-page listener plumbing can go; **service-worker requests are now routable** (1.57, Chromium), closing a gap the guard documents.
9. **`test.abort()`** (1.60) and the `signal` option on actions (1.62): abort a test the moment the egress proxy refuses a production host, instead of failing at teardown.
10. **API client**: replace the hand-written `TestApi` with **`APIRequestContext`**: the `request` fixture is standalone (own cookie jar; picks up `baseURL`, `extraHTTPHeaders`, `proxy` from config) while `context.request` shares the browser's cookies; `json<T>()` (1.63), `failOnStatusCode` (1.51), `maxRedirects` (1.52), `timing()` (1.62), **`serverAddr()`/`securityDetails()`** (1.61, proves which host answered), cookie methods (1.64), requests recorded in traces/HAR. Storage state is interchangeable between API and browser contexts.
11. **`BrowserContext.setStorageState()`** (1.59) and `storageState` `indexedDB`/`opfs`/`credentials` options: persona session reuse and the `narrowCookies` logic become smaller.
12. **`webServer.wait: /regex/`** with named capture groups exported as env vars (1.57) and `gracefulShutdown` (1.50): the mock server's `/__mock/ready` polling and port plumbing can go.
13. **Multiple `globalSetup`** (1.49): split "start broker" from "seed personas".
14. **`clock`** (1.45), **virtual WebAuthn `Credentials`** (1.61), `routeWebSocket` (1.48), TLS client certificates per context (1.46; a possible broker alternative: a per-run client cert instead of a header key), `toHaveAccessibleName/ErrorMessage` (1.44/1.50) alongside axe.
15. **Agent access to a live run**: `npx playwright test --debug=cli`, `Browser.bind()`, `PLAYWRIGHT_DASHBOARD=1`, `playwright-cli attach` (1.59), `npx playwright trace open|actions|action|snapshot` for reading traces from a terminal (1.59), and **`npx playwright mcp` / `npx playwright cli` bundled** (1.62) — no extra dependency to let an agent drive a browser.
16. Runner conveniences: `--only-changed` (1.46), `--last-failed` (1.44), `--test-list` (1.56), `TestConfig.tag` (1.57), `-G` (1.61), `omitTags` (1.63), `perfetto` reporter (1.63).

**What stays hand-written, with evidence why:** the **CONNECT egress proxy** (route handlers run once per request and "the browser follows redirects on its own"; WebSocket handshakes and `context.request` are not routed — Playwright network docs), the **loopback broker** (no built-in way to keep a header secret out of workers; mTLS per context is the only native alternative), and the **scrub/scan** (Playwright Test has no redaction; the MCP server's `--secrets` is documented as "a convenience and not a security feature"). Per-context `proxy` is documented for Chromium/Firefox/WebKit; the Chromium-on-Windows "launch with a placeholder global proxy" caveat is from memory **(unverified this round; the docs page did not expand the option)**.

## 3. Agent integration

**Landscape (verified):**
- **Agent Skills** (agentskills.io, spec in `agentskills/agentskills`): a folder with `SKILL.md` (frontmatter `name` 1–64 lowercase/digits/hyphens matching the directory, `description` 1–1024, optional `license`, `compatibility` ≤500, `metadata`, experimental `allowed-tools`) plus `scripts/`, `references/`, `assets/`; progressive disclosure (metadata ~100 tokens at startup, body <5000 tokens/<500 lines, resources on demand); `skills-ref validate`. Supported by Claude Code (native, plugin `skills/`), **Codex CLI/IDE/app** (official OpenAI docs), and per secondary sources Gemini CLI, Copilot, Cursor (`/migrate-to-skills`), VS Code **(client list unverified; agentskills.io/clients unreachable)**. Anthropic published it 2025-12-18 **(secondary)**.
- **Claude Code plugins**: `.claude-plugin/plugin.json` (only `name` required), `skills/`, `agents/`, `hooks/hooks.json`, `.mcp.json`, `bin/` (on the Bash tool's PATH while enabled — but claude.ai/Cowork refuse plugins with `bin/`), `userConfig` with `sensitive: true` stored in the OS credential store and substitutable into MCP server `env`; `claude plugin validate`; distributed via a git repo with `.claude-plugin/marketplace.json`. Cloud sessions do not load local plugins. Hooks: `PreToolUse`/`PostToolUse`/`SessionStart`/`Stop`/`PermissionRequest`/... with `command|http|mcp_tool|prompt|agent` types; exit code 2 blocks; `hookSpecificOutput.permissionDecision`.
- **AGENTS.md** (`agentsmd/agents.md`, MIT, ~25k stars): "a README for agents"; Codex reads it, Cursor keeps `.cursor/rules/*.mdc` (`description`/`globs`/`alwaysApply`) and reads AGENTS.md too **(secondary)**. Adopter list and nesting rules **unverified** (site unreachable).
- **MCP**: spec **2026-07-28** is GA (stateless core — no `initialize` handshake or `Mcp-Session-Id`; `Mcp-Method`/`Mcp-Name` headers; multi-round-trip requests; cacheable lists with `ttlMs`; auth hardening: `iss` validation per RFC 9207, `application_type` in DCR, **DCR deprecated in favour of Client ID Metadata Documents**; Tasks/Apps/EMA as extensions; Roots/Sampling/Logging deprecated with a 12-month window). TypeScript SDK **v2** split into `@modelcontextprotocol/server|client|core|node` 2.3.1 (2026-10-05); v1 `@modelcontextprotocol/sdk` 1.32.1 gets fixes ≥6 months from 2026-07-27. `registerTool` takes any Standard Schema (zod 4).
- **Playwright's own agent stack**: Test Agents (planner/generator/healer, `npx playwright init-agents --loop=vscode|claude|codex|opencode`, regenerate after every Playwright update); **Playwright MCP** `@playwright/mcp` 0.0.83 (options: `--allowed-hosts`, `--allowed-origins/--blocked-origins` "not a security boundary, do not affect redirects", workspace-root file restriction by default, `--isolated`, `--storage-state`, `--secrets` dotenv redaction, `--caps` core/tabs + vision/pdf/devtools/config/network/storage/testing, `browser_run_code_unsafe` "RCE-equivalent", Docker image, `--port` HTTP mode; README: "Playwright MCP is **not** a security boundary"); **Playwright CLI** `@playwright/cli` 0.1.22 with `playwright-cli install --skills` (writes skills for Claude Code, Copilot "and others"), sessions, `show` dashboard, `attach`; Microsoft positions the CLI+skills for coding agents (token-efficient) and MCP for long-running exploratory/healing loops.

**Recommendation: CLI first, skill second, MCP thin and optional.**

1. **One CLI is the source of truth** (`kit doctor | seed | health | run | evidence | scrub | personas`), Node 24+, ESM, no shell required on the consumer side (port the private runner's secret-staging logic to TypeScript so Windows works and the logic is testable). Every agent surface calls the CLI; nothing is implemented twice.
2. **Ship a spec-conformant skill** at `skills/e2e-testing/` (SKILL.md + `references/` for the method, `scripts/` wrappers), validated by `skills-ref` in CI, and generate from it: the Claude Code plugin (same folder as `skills/`, plus `hooks/hooks.json` with a `PreToolUse` command hook that denies Bash reads of key files/`.env`/`/proc/*/environ` as a backstop, and `.mcp.json` pointing at the kit's MCP server with `userConfig` for non-secret settings only), a `.cursor/rules/e2e-testing.mdc` with `globs`, and an `AGENTS.md` snippet. Playwright's `init-agents` output can coexist; the kit's skill should reference `playwright-cli` and `npx playwright trace` for exploration rather than wrapping them.
3. **MCP server: yes, but small and stdio-only**, built on `@modelcontextprotocol/server` v2 (2026-07-28). Tools: `personas.list` (read-only), `state.setup` (seed/reset a namespace; takes a persona set, returns ids never codes), `suite.run` (target + grep + flags; **refuses prod by config**, returns a run id and streams progress via the Tasks extension or polling), `evidence.summary`/`evidence.read` (serves only the scrubbed-and-scanned report dir, never staging), `doctor`. Mark read-only tools with annotations; make `tools/list` deterministic (spec requirement). Rationale: it gives Codex/Cursor/other MCP clients the same workflow without the plugin system, and lets a planner/healer agent get state and evidence without shelling out.
4. **Security caveats to document**: the MCP server runs as the user — it must inherit the same secret model (secret files in a 0700 staging dir, keys read only by the broker process, never in the server's own env or `userConfig`); tool results and anything read from evidence are untrusted data; no `run_code`-style tool; one run per target/slot lock; HTTP transport only on loopback with `allowed-hosts` if ever needed (auth then means CIMD, not DCR); the Playwright MCP `--secrets` redaction and origin lists are conveniences; hook-based blocking is a backstop, not a boundary (same stance as the private access policy).

## 4. Reporting and evidence

- **Emit by default**: Playwright `json` (dashboards like Buildkite Test Engine accept native Playwright JSON via the Upload API / `bktec` ≥2.7.0), `junit` (GitLab `artifacts:reports:junit`, Mergify, most CI; note 1.59 reports some failures as `<error>`), `blob` for sharding + `merge-reports`, and **CTRF** (`playwright-ctrf-json-reporter` 0.2.0; spec pre-1.0, JSON Schema normative). CTRF feeds `ctrf-io/github-test-reporter` (job summary, PR comment, annotations, flaky/fail-rate history, also accepts JUnit). Playwright's built-in `github` reporter already writes annotations; `$GITHUB_STEP_SUMMARY` is long-standing **(from memory)**.
- **Optional via `--add-reporter`**: `playwright-opentelemetry` 0.13.5 (root span per test attempt, steps/actions as children, OTLP/HTTP JSON, **injects `traceparent` into browser requests by default** — the egress guard and CORS allowlist must know; 0.x, Apache-2.0) and `allure-playwright` 3.13.0 (requires Playwright ≥1.53; `npx allure generate/open`; trace attachment supported per maintainers Feb 2026, docs "in progress" **(secondary)**).
- The scrub/scan must cover every emitted format (CTRF JSON embeds attachment paths and messages; OTel spans carry URLs and step params) — extend `evidence.mjs` per reporter and keep the "fail the run if a secret value is found" rule.

## 5. Secret handling notes

- **Child processes**: Node `spawn` inherits `process.env` unless `env` is passed — always pass an allowlist. `stdio` accepts integer fds (shared with the child) but `'pipe'` entries "are not actual Unix pipes" and cannot be read via `/dev/fd/N`. Pattern for "no env, no path": open a 0600 file in the 0700 staging dir, unlink it, pass the fd at `stdio[3]`, child reads `/dev/fd/3` once; Doppler's `--mount` (a named pipe, auto-removed on exit, `--mount-max-reads`) is the production precedent; systemd credentials (`$CREDENTIALS_DIRECTORY`, TPM-sealed `LoadCredentialEncrypted=`) for services. `crypto.timingSafeEqual` remains the comparison primitive (already used).
- **CLIs**: 1Password service accounts (`OP_SERVICE_ACCOUNT_TOKEN`, CLI ≥2.18, `op read/run/inject`, request quotas); Infisical (`infisical run --env --path --projectId`, machine identity via `INFISICAL_TOKEN`/universal auth; `secrets get --plain` is what the current runner uses — **not re-verified in docs**); Doppler (`DOPPLER_TOKEN`, `doppler run`, `--mount`). Vault/AWS CLIs were not re-checked this round **(from memory)**.

## 7. Risks and unknowns

1. **Node window**: Node 24 enters Maintenance on 2026-10-20 and 26 becomes LTS on 2026-10-28; Playwright's Docker image is Node 24. Decide `>=24.12` vs `>=26` before publishing; re-check tsdown/vitest engines.
2. **TypeScript 7** is three months old; primary announcement unreachable here; verify dts emit through tsdown and any removed compiler options before adopting.
3. **MCP 2026-07-28** is new: client support for the stateless core (Claude Code, Codex, Cursor) and the stdio story are **unverified**; building on SDK v2 may force stdio clients that still speak 2025-11-25 through compatibility paths.
4. **Playwright agent tooling churn**: `@playwright/mcp` 0.0.x, `@playwright/cli` 0.1.x, agent definitions must be regenerated each release; 1.59 changed JUnit semantics; `screen` forwarding changed in 1.64.
5. **OTel reporter adds `traceparent` to browser requests** → preflights and third-party hosts; and it is 0.x. CTRF is pre-1.0; Allure 3 trace docs incomplete.
6. **tsup 9.0.0** appeared four days ago despite the unmaintained notice — maintainership unclear; tsdown's Node floor excludes Node 22 < 22.18.
7. **npm publishing**: trusted publishing works from GitHub Actions/GitLab only; token revocation dates differ between sources; local `npm publish` needs granular tokens ≤90 days + 2FA.
8. **Per-context proxy caveat on Chromium/Windows**, AGENTS.md adopter list, Agent Skills client list, Cursor skills docs, Stripe clock limits, Twilio Verify, Mailpit search operators, Infisical `--plain`, GitHub step summary docs: **not verified against primary sources this round**.
9. **`@napi-rs/keyring` on headless Linux** silently falls back to kernel keyutils when no Secret Service exists — define behaviour for CI explicitly.
10. **Claude Code plugin limits**: `bin/` blocks claude.ai/Cowork installs; cloud sessions ignore local plugins; Agent Skills `allowed-tools` is experimental.
11. The hand-written egress proxy, broker and scrubber remain necessary; no 2025–2026 Playwright feature replaces them.
